# Assembly builder — apply BIOMT to unlock the expansion bucket

> Status: **design** (pre-claudex). The highest-value complex follow-up: on a
> diverse sample, **38%** of structures are `requires_assembly_expansion` — a
> monomeric (or sub-) ASU whose biological assembly is generated by REMARK 350
> BIOMT operators. `build_complex_supervision_examples` currently drops them. This
> builds the assembly so they become label-safe interface substrate.

## What we have

- `assembly.py` already parses BIOMT: `Biomolecule.operators` = list of 3×4
  row-major matrices `[[m11..t1],[m21..t2],[m31..t3]]`.
- `assembly_metadata` returns `(copies, is_asu)`; `assembly_is_asu is False` is
  exactly "expansion needed" (the bucket we target).
- `apply_transform(coords, R, t)` applies `y = R·x + t` to an Nx3 array.
- The supervision export is **per-chain** (`StructureSupervisionExample` = one
  chain's atom37 tensors + masks). A built assembly is a set of
  (source-chain × operator) examples with transformed coordinates.

## The approach (coordinate-level, no pdbtbx mutation)

The Python structure is read-only, but we don't need to mutate it. For each
operator `k` and each applicable source chain `c`:

1. Build chain `c`'s `StructureSupervisionExample` from the ASU (already masked
   per existing trustworthiness logic).
2. Transform its `all_atom_positions` (and `atom14`, `pseudo_beta`, frames) by
   operator `k`'s `(R, t)`. Identity operator → the original (the ASU copy).
3. Emit it as a copy with a derived chain id (`c` for identity, `c_2`, `c_3`…
   for the expansion operators), preserving `record_id` + operator provenance.

Masks (completeness, altloc, clash, chirality) are **per-residue properties of
the chain**, invariant under a rigid transform, so each copy inherits its source
chain's masks unchanged — for the *intra-chain* hazards.

## The crux: new inter-copy interfaces → RE-PREPARE (claudex)

Expansion creates interfaces **between copies that did not exist in the ASU**, so
a symmetry-mate steric overlap is unvalidated by the ASU clash scan. Codex's
verdict, adopted: **materialize the assembled structure and re-run `prepare` on
it.** Re-preparing:

- runs the SAME clash / chirality / completeness scans on the assembled
  coordinates, so the new interfaces are validated by the identical gate — no new
  clash binding, no second clash implementation;
- sidesteps the tensor-transform hazards entirely (frames / torsions / pseudo-beta
  encode ORIENTATION; transforming coords while inheriting cached masks risks
  disagreement — re-prepare recomputes everything consistently);
- gives a reference implementation; transforming prepared tensors directly is a
  later optimization, not v1.

So the mechanic is: build assembled coordinates → serialize to a loadable
structure (in-memory PDB/mmCIF) → `proteon.load` + `prepare` → existing
`build_complex_supervision_examples`. The build step's only job is correct,
deduplicated, provenance-tagged assembled coordinates.

## Provenance + chain-id collision (claudex)

PDB chain IDs are ONE character — `c_2` is illegal. Keep an internal copy key
separate from the serialized id:

```
source_chain_id, operator_index, copy_id (e.g. "A@op3"), is_identity_operator
assembled_chain_id  # deterministic, legal for the target format
# residue mapping back to source, for debugging + interface bookkeeping:
(assembled_chain_id, assembled_residue) -> (source_chain_id, source_residue, operator_index)
```

Generate legal assembled chain IDs deterministically; if the copy count exceeds
the legal chain-ID space, serialize via mmCIF or skip the structure (fail loud,
never silently merge two copies).

## Biological-validity checks (claudex)

- Operators apply to the chains REMARK 350 lists, NOT all-to-all — honor the
  parser's per-biomolecule chain applicability.
- Pick biomolecule 1 deliberately (record the choice); multiple biomolecules =
  ambiguous (already `assembly_is_asu` territory).
- REMARK 350 BIOMT only — never crystallographic `SMTRY` neighbours.
- Deduplicate operators; detect near-exact chain overlap after transform (a
  construction error / redundant operator, NOT an interface).
- Interface labels must exclude residue pairs from the SAME biological copy and
  must not confuse source-chain identity with assembled-chain identity.
- BIOMT on model 1 only, explicit (consistent with the rest of the pipeline).

## Output shape

Extend, don't replace, `ComplexSupervisionExamples`:

```python
@dataclass
class ComplexSupervisionExamples:
    ...                                  # existing fields
    assembly_operators: int = 1          # 1 = ASU already the assembly (today)
    built_from_expansion: bool = False   # True when BIOMT copies were generated
```

A built assembly's `chain_examples` keys include the operator-suffixed ids; the
gate (≥2 chains, coverage, no unmasked hazard) applies to the FULL built set.

## PR split (claudex — several PRs, not one)

1. **Materialization + provenance.** Parse/apply BIOMT, generate deterministic
   assembled chain IDs, preserve source-chain/operator mapping, dedup operators,
   handle ID-collision (mmCIF or skip). Tests: operator count, chain
   applicability, dedup, near-exact-overlap detection, collision behavior. **No
   label-yield change yet** — self-contained, the foundation.
2. **Re-prepare assembled structures** through the existing `prepare` path. Add a
   real expander fixture; prove the newly-created inter-copy clashes are seen by
   the normal validation (a clash that exists ONLY in the assembly is detected).
3. **Supervision export for built assemblies.** Apply the full interface gate to
   the prepared assembly, emit chain examples with provenance, update the
   interface-yield metric (how much of the 38% bucket is recovered).
4. *(optional)* Optimize: transform prepared tensors directly / a clash binding —
   only after PR2 establishes the reference behavior.

## Scope boundaries (v1)

- **In:** identity + rigid BIOMT operators on protein chains; per-copy coordinate
  transform of the existing masked tensors; the chosen interface-validation scope.
- **Out:** crystallographic symmetry expansion beyond REMARK 350 (no `SMTRY`);
  non-protein chains in the assembly; mmCIF `_pdbx_struct_assembly` (PDB only,
  matching the current assembly gate); the multimer tensor packing
  (asym/entity/sym ids) — still the consumer's concern.

## Test plan

- BIOMT parse → operator count matches `biological_assembly_copies` on a known
  expander (a `requires_assembly_expansion` PDB with N>1 operators).
- `apply_transform` round-trip: identity operator reproduces the ASU coordinates
  exactly; a known rotation maps a chain onto its documented symmetry mate.
- Built assembly has `operators × applicable_chains` chain examples with
  distinct, provenance-tagged ids; gate applies to the full set.
- Interface validation (scope-dependent): the chosen path's clash handling on the
  new interfaces, pinned on a real expander.

## Validation

Re-run the interface yield with the builder on: how much of the 38%
`requires_assembly_expansion` bucket becomes label-safe interface substrate.
