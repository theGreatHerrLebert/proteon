# NESSie.jl oracle harness

Offline fixture generator for `proteon-electrostatics`, the BEM continuum-
electrostatics port. This is the **P0** deliverable of `TO_ELECTROSTATICS.md`:
stand up NESSie.jl as an oracle, emit deterministic JSON, gate the Rust port
against it layer-by-layer (the proteon way — cf. `ball-py` for the SES port).

**Not a proteon build or runtime dependency.** It lives in its own pinned Julia
project; the small fixtures it produces are checked into the
`proteon-electrostatics` test tree.

## One-time setup

```bash
# Requires Julia 1.10+ on PATH.
julia --project=tools/oracle/nessie -e 'using Pkg; Pkg.instantiate()'
```

This resolves `NESSie@1.5` and `JSON` into the project's own manifest. **Commit the
generated `Manifest.toml`** — the `[compat]` bounds alone are a range, not a pin;
the manifest (plus the `nessie_tree_hash` in each fixture's provenance) is what makes
a regeneration reproducible.

## Generate fixtures

```bash
julia --project=tools/oracle/nessie tools/oracle/nessie/harness.jl <out_dir>
```

Writes the starter corpus (one Born ion, from NESSie's bundled `data/born`):

| File | Layer | Contents |
|------|-------|----------|
| `collocation_na.json`       | L1 | analytic Laplace SL/DL collocation matrices + element geometry + obs points |
| `yukawa_na.json`            | L2 | regular-Yukawa SL/DL collocation matrices at the model's yukawa |
| `assembly_kernels_{local,nonlocal}_na.json` | L3 | kernel building-block matrices (**partial** assembly oracle — see caveats) |
| `solve_{Local,Nonlocal}ES_{gmres,blas}_na.json` | L3 | Cauchy data `u,q,[w]` + `umol,qmol`, with ordered elements/obs-points/charges/params |
| `post_{local,nonlocal}_na.json` | L4 | `rfenergy` + `espotential` with **distinct** interior/exterior/surface sample sets per `:Ω/:Σ/:Γ` |
| `analytic.json`             | L4 | closed-form Born energies (local + nonlocal) + each ion's charge/radius/params — independent ground truth |

Every file carries a `provenance` block (NESSie version + **tree-hash** + Julia version).

## The six dumps (and what they gate)

See `TO_ELECTROSTATICS.md` §3–§4. In short: `collocation`/`yukawa` gate the kernels
(L1/L2), `system` gates **assembly** entrywise (an LU of proteon's *own* matrix
cannot — it inherits assembly bugs), `solve` gates Cauchy data (L3), `post` gates
parity of energy/potentials (L4), and `analytic` is the closed-form science gate.

## Caveats / TODO

- **`assembly_kernels_dump` is a PARTIAL assembly oracle until P0.5.** It gates
  kernel-block parity only — the full assembled 2/3-block system + RHS + dielectric
  factors + jump terms are pinned by the formulation spec (`devdocs/
  ELECTROSTATICS_FORMULATION.md`, plan §1b). Finish it (emit the assembled system)
  once the blocks are written down; do not treat the current output as a full
  assembly gate.
- **Canonical convergence mesh.** The Born/Xie convergence claim runs on proteon's
  own `icosphere` (`proteon_core::surface::mesh::icosphere`, vertices on the exact
  sphere) emitted as OFF so both sides consume the *same* mesh. Add an
  `analytic_sphere_*.off` ladder + a `readoff`-based loader path here when wiring P5.
- **Independent oracles** beyond NESSie (plan §3): high-precision numerical
  quadrature of the kernels (Duffy/subdivision design — *not* generic adaptive),
  externally-generated CAS/mpmath closed-form fixtures, and an APBS local-Poisson
  cross-check. Generated by separate tools; not in this harness.
- Extend the corpus with Xie spheres, the analytic-sphere ladder, and one small
  protein as the layers come online. Keep dense convergence runs
  regenerate-on-demand, not checked in (plan Q5).
